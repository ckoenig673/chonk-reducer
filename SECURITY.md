# Security Policy

## Reporting a Vulnerability

Please use this repository's private GitHub vulnerability-reporting flow. Do not open a public issue or pull request for an active vulnerability.

Include a concise description, affected component, impact, and the minimum reproduction details needed to validate the issue. Do not publish credentials, tokens, webhook URLs, encryption keys, personal data, or weaponized proof-of-concept material.

If a secret was exposed, revoke or rotate it before sharing follow-up details.

## Supported Versions

Security fixes are applied to the latest release and the latest code on `main`. Historical releases and unsupported local modifications may not receive fixes.

## Response Expectations

Reports will be reviewed privately. Public disclosure should wait until a fix or mitigation plan is available.
